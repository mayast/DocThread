Design additions and approval boundaries

The normal path stays small. Extra controls appear only when there is input or an outcome to protect. These additions mitigate the identified gaps; a mockup cannot make durability, source affinity, or delivery guarantees true.

Do not add an anchor-confirmation state, silently move a thread, or equate Resolve with approval.

Preserved: rendered document, selection anchors, question/suggestion/blocking data, contextual Reply/Resolve and suggestions, source-write confirmation, editor, unified AI review, summary, optional grounding, recents, sample, sharing and inbox. No mandatory role, intent selection or setup.

Visual and intent decision: keep the existing GitHub Primer direction: GitHub typography, neutral surfaces, green primary actions and complete outlines, with no Fluent styling or decorative accent stripes. Question, Suggestion and Blocking stay visible together and selectable in one click. Question remains the default; choosing a category is not a prerequisite to posting. The optional "Suggest an edit" control adds an exact replacement independently of the Suggestion category.

Implementation constraint: #128 is a UX improvement, not a presentation redesign. Reuse the application's existing Primer-consistent styles, components, typography, colors and button treatments. Change control placement, grouping, wording or interaction only to address the ACs; do not translate this mockup into a replacement theme. Separate frequent review actions from metadata and utilities using existing neutral separators and spacing, not accent stripes, extra menus or instructional labels. Completion depends on AC evidence and the stated validation gates, not visual novelty.

Thread visibility: show complete comments and thread actions without truncation or a fixed-height nested scroller. The rail grows with its content; the new-comment composer appears only after selecting a passage. Short discussions should fit the available desktop space. Longer discussions and narrow screens use page scrolling, retaining the original quote and passage navigation.

Wording decision: category and thread-state labels carry no product-authored definitions, prescriptions or approval disclaimers. Reviewers decide how to use Question, Suggestion, Blocking and Resolve. Guidance is limited to finding controls, understanding actual access and save outcomes, or recovering input. This replaces the earlier proposal to explain Blocking.

Direct controls: search, filter and sort are visible in the comments rail. Thread actions have no overflow menu. Copy link attempts the copy directly and opens a selectable fallback only on failure. Tools stays a single flat menu for secondary document and AI actions; optional AI grounding is disclosed within the AI panel.

Changes from Maya's static mockup: one global Edit/AI entry point under Tools; Filters no longer contains AI; the coach becomes an inline session hint. The older standalone readiness button is not reintroduced. The prototype's rail composer is retained.
