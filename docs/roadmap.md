# Roadmap


The roadmap below is a **single, ROI-prioritized backlog** tracked on the
**[GitHub Issues board](https://github.com/gim-home/DocThread/issues)** — each item links to its
issue (scoped with acceptance criteria and non-regression notes). It merges the collaboration/UX work
with the **AI-native SDLC** capabilities into one ordered list. **Theme** marks each item as **Core**
(review/collaboration surface), **AI** (AI-native SDLC), or **Core+AI** (connective tissue for the
human + AI loop). Order = ROI (impact ÷ effort), with dependencies and strategic pull toward the
mission — a **collaboration operating system for documents** where humans and AI review together —
breaking ties.

**Recently shipped:** [Request review (#51)](https://github.com/gim-home/DocThread/issues/51) is live via
[PR #157](https://github.com/gim-home/DocThread/pull/157) — the GitHub channel creates a **review
Issue** (not a pull request; the existing document-edit PR flow is unchanged), with duplicate detection,
reviewer assignment, and status refresh. Azure Repos and Azure Boards channels remain visible but gated
for Phase 2. [Share-for-review (#111)](https://github.com/gim-home/DocThread/issues/111) and [AI proposed replacement — Accept fix (#108)](https://github.com/gim-home/DocThread/issues/108) are live (issues pending close); [Skill-aware AI review & suggestions (#92)](https://github.com/gim-home/DocThread/issues/92)
is live via [PR #125](https://github.com/gim-home/DocThread/pull/125) and the Azure Static Web Apps
deployment. The shipped **Run AI Review** button now combines readiness scoring, review findings, and
proposed replacements in one panel; users can ground output with a linked/selected `REVIEW.md` and/or
any Markdown/text skill file from a repo path, URL, upload, pasted content, or configured
`VITE_SKILL_PATHS`.

**Size legend:** S ≈ ≤1 day · M ≈ 2–4 days · L ≈ 1–2 weeks · XL ≈ 3+ weeks. **Order = ROI (impact ÷ effort)**, with priority and size breaking ties; `⏸ blocked` and `🧪 larger bet` items are ranked in place but flagged (dependencies / high effort keep them off the near-term path).

**Impact / ROI** are relative estimates. The **strategic core** — the shipped AI reviewer pass (#43), AI-readiness score (#44), skill-aware grounding (#92), Summarize a review (#30), and **request review (#51)**, plus the backlog **MCP API (#45)** — turns DocThread from a nicer comment box into a **collaboration operating system for documents**: authors request review through a real GitHub review Issue (#51), humans and AI review inline (#43/#44/#92), and feedback flows to coding agents through the MCP API (#45). They compound; with the cheap wins (Deep-link, Reactions, Notification center, Spell check, Edit-mode preview, formatting toolbar, comment search, suggested edits, AI-suggested edits, and share-for-review) already shipped, the remaining strategic core (MCP API) now leads the backlog.

A second cluster — **the audit trail** (traceability #48, artifact-chain lineage #88, provenance #46, approval gates #90) plus the **governance-of-AI** work (the shipped REVIEW.md policy #89 and shipped skill-aware AI #92) — makes DocThread relevant to the emerging **[AI-native SDLC](https://claude.com/blog/the-ai-native-sdlc-playbook)**, where every stage commits a version-controlled markdown artifact and the committed chain *is* the audit record. #89/#92 ground the AI reviewer and suggestions in the org's encoded standards (REVIEW.md + skills), positioning DocThread as the review surface for that workflow's machine-readable governance artifacts (`spec.md`, `plan.md`, `CLAUDE.md`, `REVIEW.md`, skills). Continuous evals and autonomous production monitoring from that playbook are deliberately **out of scope** — they belong to CI/ops, not the document-review surface.
